public ResetOutcome run(DbDispatcher dispatcher) {
    try {
        dispatcher.connect();
        var record = fetchControlRecord(dispatcher);
        var result = modifyControlRecord(dispatcher, record);
        dispatcher.commit();
        return ResetOutcome.success(record, result);
    } catch (DmsException e) {
        dispatcher.rollback();
        return ResetOutcome.failure(99, e);
    }
}

private JvControlRecord fetchControlRecord(
        DbDispatcher d) {
    var result = d.selectOne(
        """

         WHERE CONTROL_RECORD_NAME = ?

// Java 21
private JvControlRecord modifyControlRecord(
        DbDispatcher d, JvControlRecord rec) {
    logger.info("JV-NUMBER=%d", rec.jvNumber());
    var updated = rec.withJvNumber(1);
    d.update("""
        UPDATE CONTROL_RECORD_TABLE
           SET CONTROL_RECORD_DATA = ?
         WHERE CONTROL_RECORD_NAME = ?
           AND CONTROL_RECORD_NUMBER = ?
        """, updated.toBlob(),
        "JV-CONTROL-REC", 1);
    return updated;
}

Risk 2High

Binary↔display JV-NUMBER conversion

JV-NUMBER stored as USAGE BINARY inside JV-CONTROL-REC; the persisted CHAR(400) column uses display form.

Evidence
JV-CONTROL-REC.cpy:6, CONTROL-RECORD-TABLE-IO.pco:21-28, 257-266
Mitigation
Java reads CONTROL_RECORD_DATA as display string, slices JV-NUMBER at offset [24:30], parses as zoned decimal. Never crosses DB boundary in binary form.
SME Action
Confirm no caller depends on the in-memory binary representation outside CONTROL-RECORD-TABLE-IO.
Affected Components
LABA05, CONTROL-RECORD-TABLE-IO, JV-CONTROL-REC
Risk 3High

Credential files /tst/.oralogin, /tst/.orapasswd

Legacy program reads plain-text credentials from filesystem. Security risk — must not be reproduced.

Evidence
DBIO.pco:33-38 (file SELECTs), DBIO.pco:41-45 (USRID-REC, PASSWD-REC)
Mitigation
Java uses environment variables or managed secrets store (e.g., AWS Secrets Manager / HashiCorp Vault). No credentials in committed files.
Affected Components
DBIO, LABA05.pl, LABD20-JV.pl
Risk 4Medium

Dynamic subroutine dispatch in DBIO

DBIO constructs IO-module names at runtime by string concatenation.

Evidence
DBIO.pco:228-260 (STRING loop), DBIO.pco:311-320 (CALL IO-SUBROUTINE)
Mitigation
Two static paths documented: JV-CONTROL-REC → CONTROL-RECORD-TABLE-IO; embedded SQL for LABD20. Java uses typed dispatch with UnresolvedDispatchPathError for unknown targets.
Affected Components
DBIO, CONTROL-RECORD-TABLE-IO
Risk 5High

Fixed-width record layout byte precision

Off-by-one in TST123-COMMENT-REC parsing produces silently wrong field values. Approver width: 14 vs 20 bytes ambiguity.

Evidence
LABD20.pco:43-55 (FD layout, line 55 active=14, line 54 commented=20)

Java parser uses explicit byte offsets per FD (14-byte approver). Total record = 300 bytes. Unit tests assert each byte boundary.
